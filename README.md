# 皮影古件演出保全

鹤峰春生皮影剧团的同一后台：把**影偶实体、历史年代、部件状况、修补层次、可用剧目、
复制替身、收纳环境、演出排练、借用责任、学徒操作资格**纳入一条只追加的领域事件流，
让演出经理、修缮师、传承人在同一语义上协作。

## 一条主线：老件是否上台，由三因子共同决定

```
放行 = 保存状态通过  且  环境安全  且  授权齐备
```

1. **保存状态**：本场派戏用到的部件无一冻结（开裂/虫蛀/酥脆，或已修复但尚未复检）。
2. **环境**：演出地温湿度在安全区间（默认 45–65 %RH、15–28 ℃）。
3. **授权**：操控人具备对应文物等级的接触资格；一级文物另需**逐场书面特批**且师傅在场。

> **节目已售票从不构成放行理由。** 售票只是被带回给经理看的事实，不参与任何一个因子。
> 书面特批只能解除“一级文物默认不上台”这一等级限制，**不能覆盖部件冻结或环境越限**。

## 关键保全规则

- **报损只冻部件，不株连整件**：发现开裂/虫蛀时，仅相关部件冻结，同件其他完好部件仍可用。
- **为已排场次找核准替身**：老件部件冻结时，只能改派该角色**已核准**、能演本剧、状态完好的
  复制品；没有替身就撤角或待修复复检，**不得带伤硬演**。换角后旧许可自动失效，须重新核验。
- **修复分层、只追加**：每次修复都保留材料与手法，形成独立层次；返工是新的一层，
  旧痕迹永不覆盖。修复后部件为“已修复待复检”，修缮师复检合格才解冻。
- **学徒逐级成长、师傅复核**：操控/制作/修补三科分层训练，上一层复核通过才能进下一层；
  末级通过后由本门师傅授予独立资格。只有本门师傅可复核与授权。
- **未成年人硬封顶**：未成年学徒只能接触**获准级别（仅复制品）**的道具；
  训练层级在涉真品处封顶（操控科止于“复制品独立”、修补科止于“复制品试修”），
  即使日后取得资格，独立接触真品仍被禁止。
- **单一当前位置**：借用、多人交接、在途离线记录、归还清点同走一条保管链。
  - 离线事件带 `(client_id, client_seq)` 幂等键与链上前驱 `previous_event_id`；
    弱网重传同一序号只产生一个位置。
  - 两台离线终端基于同一链尾各自交接即判**分叉**：两种说法都留证，当前位置立即冻结为
    “位置争议（待复核）”，复核归位前拒绝一切借出/交接/归还——**同一物件永不出现两个当前位置**。
  - 归还按在册部件清点，缺件明确登记为不完整，不得当作完好入库。

## 三类角色各取所需

- **演出经理** `managerShowStatus / substituteRole`：开演前逐角色三因子总览，
  被冻老件直接给出可改派的核准复制品，在不伤老件的前提下完成换场。
- **修缮师** `restorerTrace`：从一处损伤追到它的报损记录、历次修复层次、
  报损前最近使用场次与当时环境读数、当前保管位置。
- **传承人** `masterApprenticeReport`：每名学徒各科分层进度、师傅复核、
  是否真正具备独立操控/制作/修补能力，以及未成年封顶后的实际可接触级别。

## 目录结构

```
contracts/domain.schema.json  由事件目录生成的契约（类型-聚合-负载），勿手改
src/
  policy.js      文物等级/环境阈值/训练层级/接触级别等领域策略
  contracts.js   事件目录：24 类事件的信封+负载校验
  validator.js   共同信封基础校验（保持向后兼容）
  store.js       追加式事件存储：版本号、幂等、离线键
  projection.js  事件流 → 影偶/环境/演出/保管链/学徒 读模型
  errors.js      DomainError（业务拒绝）/ ContractError（契约不合法）
  services/
    inventory.js    登记、巡检报损、分层修复、复检、替身核准、环境
    performance.js  排期派戏、三因子核验、换角替角、临场复检、收场
    custody.js      借用、离线交接、分叉争议、归还清点、复核归位
    training.js     学徒分层训练、师傅复核、独立资格、接触级别
    app.js          装配 + 三类角色查询视图
scripts/
  build-schema.mjs  从事件目录重新生成 JSON Schema
  scenario.mjs      端到端情景，并写出 data/sample-flow.json
data/
  sample.json       单条合规事件
  sample-flow.json  端到端情景产生的完整事件流（脚本生成物）
tests/              node --test 契约/影偶/演出/保管/学徒/端到端
```

## 事件（只追加，不改写）

事件一经接收，其 `event_id / occurred_at / version` 不再原地改写；业务更正只能产生后继事件。
`version` 按聚合（`aggregate_type + aggregate_id`）单调递增。离线终端在信封上附带：

```json
"offline": { "client_id": "device-向经理", "client_seq": 1, "previous_event_id": "…上一链尾…" }
```

事件覆盖：影偶登记/剧目、巡检、报损、修复、复检、替身核准、环境记录；
演出排期、派戏、核验请求、放行/拒绝、换角、收场；
借出、交接、归还、位置争议、复核归位；学徒入门、训练登记、师傅复核、资格授予。

## 本地检查

```bash

npm run typecheck # tsc 类型检查

```
